# СППР — Ситуационное управление проектом

Система поддержки принятия решений (СППР) на основе **метода ситуационного управления** (Поспелов Д.А.).
Реализована как **Progressive Web App** — запускается в браузере смартфона, работает офлайн.

---

## Демонстрация

Откройте `index.html` в браузере или разверните на любом веб-сервере.
На смартфоне: откройте в Chrome/Safari → «Добавить на главный экран».

## Метод ситуационного управления

### Теоретическая основа

Метод ситуационного управления был разработан Д.А. Поспеловым в 1970-х годах как подход к построению интеллектуальных систем управления. Ключевая идея: **управляющее решение определяется не заранее заданным алгоритмом, а текущей ситуацией**, описанной набором признаков.

### Основные понятия

| Понятие | Определение |
|---------|-------------|
| **Дескриптор** | Признак, характеризующий одну сторону ситуации (например, «состояние бюджета») |
| **Значение дескриптора** | Конкретное состояние признака на шкале значений |
| **Текущая ситуация** | Вектор S = {(d₁, v₁), (d₂, v₂), ..., (dₙ, vₙ)} |
| **Правило** | Пара (Sᵢ, Rᵢ) — эталонная ситуация и соответствующее решение |
| **База знаний** | Множество правил KB = {(S₁,R₁), ..., (Sₘ,Rₘ)} |
| **Степень подобия** | σ(S, Sᵢ) ∈ [0,1] — мера близости текущей ситуации к эталону |

### Алгоритм работы

```
1. Пользователь задаёт текущую ситуацию S — выбирает значения дескрипторов
2. Для каждого правила i в базе знаний:
      σᵢ = Σ(wⱼ · sim(vⱼ, vᵢⱼ)) / Σwⱼ
3. Правила ранжируются по убыванию σᵢ
4. Возвращаются топ-N правил с σᵢ ≥ порог
5. Пользователь получает рекомендации и план действий
```

### Функция подобия значений

Для **порядковых шкал** (применяется линейный спад):

```
sim(a, b) = 1 − |idx(a) − idx(b)| / (|шкала| − 1)
```

Для **номинальных шкал**:

```
sim(a, b) = 1 если a = b, иначе 0
```

**Пример** для дескриптора «Расписание» со шкалой [опережение, в_срок, отставание, критическое]:

| Текущее | Правило | sim |
|---------|---------|-----|
| в_срок | в_срок | 1.00 |
| отставание | в_срок | 0.67 |
| критическое | в_срок | 0.33 |
| опережение | критическое | 0.00 |

### `js/engine.js` — класс `SituationalEngine`

| Метод | Описание |
|-------|----------|
| `constructor(kb)` | Инициализация с базой знаний, построение индексов шкал |
| `similarity(current, rule)` | Вычисление σ(S, Sᵢ) ∈ [0,1] |
| `analyze(current, topN, threshold)` | Анализ ситуации, возврат топ-N правил |
| `getAttributes()` | Список дескрипторов с метаданными |
| `_valueSimilarity(attrId, a, b)` | Подобие двух значений одного дескриптора |
| `_scoreToConfidence(score)` | Перевод числового score в уровень уверенности |

### `js/knowledge-base.js` — объект `KNOWLEDGE_BASE`

```js
{
  meta: { domain, version, author },

  attributes: {
    <attrId>: {
      label: string,   // отображаемое название
      icon:  string,   // эмодзи
      type:  'ordinal' | 'nominal',
      values: [{ id, label }, ...]
    }
  },

  rules: [{
    id:        string,   // уникальный идентификатор (R01…)
    name:      string,   // краткое название ситуации
    situation: { <attrId>: <valueId> },  // эталонная ситуация
    weights:   { <attrId>: number },     // веса дескрипторов (default: 1)
    priority:  'ok' | 'warning' | 'critical',
    decision:  string,   // краткая формулировка решения
    rationale: string,   // обоснование
    actions:   string[]  // список конкретных действий
  }]
}
```

## Дескрипторы

Система использует **6 дескрипторов** на порядковых шкалах (4 уровня каждая):

| # | Дескриптор | Шкала (от лучшего к худшему) |
|---|-----------|------------------------------|
| 1 | 📅 Расписание | опережение → в срок → отставание → критическое |
| 2 | 💰 Бюджет | экономия → норма → перерасход → критический |
| 3 | 👥 Команда | высокая → нормальная → снижение → кризис |
| 4 | ⚠️ Риски | низкий → умеренный → высокий → критический |
| 5 | ✅ Качество | отличное → хорошее → удовлетворительное → неудовлетворительное |
| 6 | 🤝 Заказчик | доволен → нейтрален → недоволен → конфликт |

## Как расширить базу знаний

Добавьте новое правило в массив `rules` в файле `js/knowledge-base.js`:

```js
{
  id: 'R16',
  name: 'Название ситуации',
  situation: {
    schedule: 'delayed',   // один из: ahead | on_time | delayed | critical
    budget:   'normal',    // один из: savings | normal | overspent | critical
    team:     'low',       // один из: high | normal | low | critical
    risks:    'high',      // один из: low | medium | high | critical
    quality:  'satisfactory', // один из: excellent | good | satisfactory | poor
    customer: 'neutral'    // один из: satisfied | neutral | dissatisfied | critical
  },
  weights: {
    // Укажите веса для наиболее значимых дескрипторов (default: 1)
    schedule: 3,
    risks: 2
  },
  priority: 'warning',    // ok | warning | critical
  decision: 'Краткая формулировка решения',
  rationale: 'Обоснование — почему именно такое решение.',
  actions: [
    'Конкретное действие 1',
    'Конкретное действие 2'
  ]
}
```

Не обязательно заполнять все дескрипторы в `situation` — система поддерживает **неполные правила** (partial matching).

## Добавление нового домена

Можно создать альтернативную базу знаний для другой предметной области (медицина, производство, логистика и т.д.):

```js
const MY_KB = {
  meta: { domain: 'Моя предметная область', version: '1.0' },
  attributes: {
    attr1: {
      label: 'Параметр 1', icon: '📊', type: 'ordinal',
      values: [{ id: 'v1', label: 'Значение 1' }, ...]
    }
  },
  rules: [ /* ... */ ]
};

// Использование:
const engine = new SituationalEngine(MY_KB);
```
